2. 摘要

核心结论: 统一变量对照实验 (唯一自变量 ENABLE_PREFIX_SHARING 0/1) 证实 — PrefixSharing 使训练 step 时间中位数 75.7s → 56.6s (↓25%), 推理节点 HBM 峰值 3577MB → 3423MB (↓154MB)。训练节点平均 HBM 4233MB vs 4653MB (↓9%)。PS 复用率稳定 0.26-0.28, restore 25/25 全部命中。

3. 方法与受控条件

两组实验按同一部署链路执行, 唯一差异为 PS 开关。PS 控制面: ENABLE_PREFIX_SHARING env 由 config.py 读取; 显式 prefix_sharing_config 值优先于 env — baseline 组通过脚本显式 enable_prefix_sharing: false 钉死关闭, ps 组置 true。训练侧前向 (torch_ref backend) 由 [PS][audit] 日志行确认开启。

严格归因条件
数据集 / 节点 / GPU_MEM_UTIL / MAX_PROMPT_LENGTH / steps 全部相同 (config diff 逐项验证), 唯一变量 = ENABLE_PREFIX_SHARING 0/1。

PS 机制要点

  • 复用发生在训练侧前向 (G2 Attention prefix KV reuse, torch_ref backend, after_read_config enable_prefix_sharing=True)
  • 每 step 复用 128 tokens 前缀 (reuse 数据集 106-token 共同 system prompt + padding)
  • restore 25/25 全命中 — 复用路径无失效

8. 可信度边界 (对照实验设计)

严格归因条件已满足:

维度是否受控说明
数据集✅ 同reuse_train.parquet 两组相同
节点✅ 同189/36 两组相同
GPU_MEM_UTIL✅ 同0.70 两组相同
MAX_PROMPT_LENGTH✅ 同384 两组相同
steps✅ 同8 steps, 同剔除规则
唯一变量✅ENABLE_PREFIX_SHARING 0/1 (config diff 验证)

剩余不确定性

  1. 顺序效应: 两组顺序执行 (baseline 先, ps 后), 节点温度/邻居负载差异不可排除。量级小 (同 NFS 同镜像同驱动)。
  2. step 8 checkpoint 干扰: 训练终点必保存 checkpoint, step 8 时间两组均不可比 (ps 156.6s vs baseline 125.9s 差异可能与保存时 IO 竞争/状态有关), 已从中位数剔除。
  3. 采样粒度 5s: HBM 采样可能漏掉亚秒级瞬时峰值, 但两组同粒度, 对比方向可靠。

9. 结论

  1. PS 性能收益成立: 统一变量下 step 时间中位数 ↓25%, 收益稳定 (step 2-7 全部 −13.5s 以上), 与 PS 机制预期一致。
  2. PS 复用功能完整: ratio 0.26-0.28 稳定, restore 25/25 命中, provider/reuser 结构 1/1/1 正常。
  3. PS 不增加显存: 推理节点峰值 ↓154MB (无额外 KV 预留), 训练节点均值 ↓9%, 峰值相当。
  4. 对照实验有效: 唯一变量 = ENABLE_PREFIX_SHARING, 其余全受控, 归因可信。
