指标口径：除特别说明外，本报告的 Pearson 指同一批 rollout token 上，训练侧重算概率与推理侧记录概率的 Pearson 相关系数；它不是所有实验都相同的“全词表 logprob 一致性”。不同模型规模、响应长度、算法和并行配置的数据不直接横向排名。

“完整”在本报告中指覆盖主要路线分叉、瓶颈族、有效修复、被推翻的中间结论和当前未决项，不复制数百次启动脚本的逐条错误日志。每个结论可用下方 S 编号追溯到原始报告。

2026-10-15 → 10-20

从现成引擎开始：四节点 SFT 先证明“能训练”，再证明“能复现”首步复现；逐步位级复现不成立

本章回答：torchtitan-npu 作为训练引擎的起点是否可靠，为什么不能把一次成功直接当成适配完成。 S0 S1

算力与权重规模

现象与根因：四节点 32×910B3 无法同时容纳 384 专家与 Engram 宿主表。采用官方 384 专家权重的真实前 64 专家截断，EP32、真实视觉 SFT 数据和引擎公开配置插件；禁止随机初始化。

处理与结果：四节点 64 专家 SFT 完成五步，首步 loss=6.71309，HBM=37.12 GiB，引擎 749 个文件零改动。

复现假设错误

现象与根因：预注册要求五步 loss 逐点误差 ≤1e-4，但反向归约存在约 2e-5 相对非确定性，top-6 路由边界翻转将其放大到 1e-2 量级 loss 差。

处理与结果：首步与配置逐位复现，五步逐点门保留 FAIL。结论改为区分“功能复现”和“位级轨迹复现”，没有用重跑刷值或事后放宽判据。

2026-10-21

SFT 接入 RL：先让权重、数据和推理服务可消费SFT→RL 权重装配闭合

本章回答：torchtitan 的 SFT 产物怎样成为 verl/推理服务真正可用的初始权重。 S2

权重键面污染与导出配置

现象与根因：权重分片含 46,408 个遗留量化 scale 键，原生导出还受 load-only、float32 默认值和 tokenizer 资产约束。

处理与结果：清除 scale 残留，以引擎公开 HF 导出能力生成 bf16 权重，强制 index=physical=8,864 键，补 chat template、tokenizer 和 config。

训练有效性证明

现象与根因：只装载权重不能证明训练有效，gate.bias 未变化也需要显式解释。

处理与结果：四节点五步 SFT 的 loss 从 8.26029 降至 7.74767；采样参数有位变化，HF 导出与 RL 初始视图装配通过。

2026-10-22 → 10-26

第一次 RL 集成：难点从模型算子转移到分布式框架契约引擎分项通过；端到端接入未闭合

本章回答：为什么“torchtitan 能 SFT”并不等于“verl 能直接用它做 RL”。 S3 S4 S5

权重布局错误

现象与根因：专家 TP 合并误命中与列块切分使一次导出膨胀到约 706GB，推理重载出现 2304/9216 形状冲突。

处理与结果：修正专家命名与布局，经 CPU 逐位测试后，导出回到约 197GB；推理逐键重载与权重身份核验通过。

FSDP/SPMD 网格身份与注解

现象与根因：双 Trainer、尺寸 1 的 CP 轴和 FSDP 存储校验对网格对象身份、注解持久化要求不一致，出现“已注解但仍不完整”的假修复。

处理与结果：显式交接训练核网格，actor/ref 分上下文，逐步通过仅 actor 引擎、actor+冻结参考前向、真实 GRPO 训练步和双引擎构造四项验证；尺寸 1 轴契约问题不再用补注解硬闯。完整端到端 RL 仍受 HF config、rollout 注册与依赖闭包阻塞，未宣告完成。

运行环境与设备访问

现象与根因：只读引擎树仍有 logs/outputs 写点；符号链接目标超出容器挂载；非特权容器遭 UDA 设备占用拒绝。

处理与结果：写点迁移到独立工作目录、只读补挂 /data/model，按用户裁决以 --privileged 作为集群绕行。原生一步 SFT 等价验证 14/14 通过，但特权模式和集群根治被记录为运维债。

2026-10-26 → 10-29

主线重建：减少私有补丁，先完成 64 专家 RL，再恢复 Engram64 专家端到端与一致性通过

本章回答：怎样把早期大量集成补丁收敛为可维护的 verl 主线原生栈。 S6 S7 S8 S9 S10

推理依赖与训练栈解耦

现象与根因：训练镜像没有 vLLM，但 verl 默认 rollout 注册会强制导入；依赖闭包和自定义训练入口持续扩大。

处理与结果：改用 verl 主线与 torchtitan 训练核，外置 serve 注册、rollout 客户端、checkpoint manager 和 HF config 独立注入；先 KL-off，后续升级另行验证。

同步协议与专家导出死锁

现象与根因：主线 get_per_tensor_param 对专家栈的 full_tensor 路径死锁；早期 serve 消息队列还会让 worker 读取不同步号。

处理与结果：dense 走 full_tensor，专家走显式 EP all_gather；唯一步号、原子提交与重建服务清掉旧消息。8,518 键、约 197GB、重载差值 0，随后完整 GRPO 通过。

短训一致性与 Engram

现象与根因：一致性需要在同一批采样 token 上比较，而非仅看 loss。Engram 还引入 F8_E8M0 元数据、开关反转和独立行级更新通道。

处理与结果：64 专家六步 token 概率 Pearson=0.998820→0.997347，均≥0.995。补 F8_E8M0 映射、修正开关、接通 Engram 行级 delta 与 gate 六键，随后三步 Pearson 0.99904–0.99929。

Engram 的宿主内存墙

现象与根因：两节点 EP16 时 SparseAdam 为全表预分配稠密矩量，节点约需 1.18TB 主机内存；减到 32 专家也无效，因为表行数与专家数无关。

处理与结果：采用四节点 EP32 分摊宿主表与优化器状态；两节点降专家方案被算术与实跑共同否决。

全量 384 专家：从减专家机制验证走向真实模型规模30 步全量 GRPO 完成

本章回答：全量 BF16 模型能否进行真实端到端 RL，而不只是小规模链路冒烟。 S11

全量权重与通信规模

现象与根因：384 专家 BF16 需要更大专家分片规模，推理还受到 TP>8 分组和旧版长上下文算子约束。

处理与结果：训练采用 16 节点 EP128，推理采用四节点；移除 Engram 复杂度，继承主线训练与 safetensors 权重链。

真实训练成效

现象与根因：仅有有限 loss 不能回答模型能力是否提升。

处理与结果：30 步 GRPO 零崩溃、耗时 8h16m；100 题 MATH 考卷 pass@1 从 0.43 到 0.64。奖励后段回落如实保留，不外推为持续收敛。

32K 旧推理栈崩溃

现象与根因：vllm-ascend 0.27.1 在 32K decode 两次跨节点复现 EE9999/aclnnMul/507035。

处理与结果：该配置未通过，转算子/CANN 缺陷线；不把失败隐藏在全量训练成功里。

2026-10-29 → 11-05

推理换栈与长上下文：原生重载替代私有热更，CP 契约逐层补齐全量 32K 链路通过；长期训练仍有边界

本章回答：0.30 推理升级、上下文并行和权重格式如何一起解决旧栈崩溃与长序列显存问题。 S12 S13 S14 S15 S16 S17

热更协议与文件格式不兼容

现象与根因：0.27 私有扩展不能原样迁移；0.30 原生 reload_weights 只接受 HF 目录，早期 npy 和挂载缺失会被误当仓库名。

处理与结果：训练侧直接流式写 HF safetensors/index，推理用原生 reload_weights。连续 30 次重载全绿，热态 p50=47.3s，HBM 漂移 0。HTTP 200 不再单独视为成功，必须抽样读回参数。

CANN 算子包与运行时注册

现象与根因：自建 9.3 包漏 sparse_flash_mla_metadata，静默回落到只接受 cmp_ratio=4 的旧实现；metadata 尺寸还有 1024/2048 不一致，JIT 共享缓存出现 ESTALE。

处理与结果：补全四算子、对齐 metadata 尺寸、JIT 改节点本地预热；以 cmp_ratio=1/2/4 行为验证实际生效包。

算子“存在”不等于“已注册”

现象与根因：CP 训练首前向缺 torch.ops 符号，根因是训练进程没有 import cann_ops_transformer，不是镜像缺包。

处理与结果：CP>1 进程用 sitecustomize 预载同一包并断言四算子；编译缓存与导入注册分开验收，避免重复 DEF 注册。

CP 布局与逐文档对齐

现象与根因：旧布局下 RoPE 全长张量与本地 positions 长度不一致，verl 还绕过原生 dataloader 的 per-doc 对齐。

处理与结果：升级 torchtitan-npu master，采用 doc_chunk，补 verl 逆置换 gather、全局 positions 与逐文档 padding。CP=1 回归 Pearson=0.998213，CP=2 引擎探针通过。

长上下文训练结果

现象与根因：CP=32 将 32K 序列分摊到各 rank，解决全量长序列的激活压力。

处理与结果：全量 32K DAPO 三步 Pearson=0.99739/0.99732/0.99768。后续 24 步无崩溃，22/24 步≥0.995；响应长度塌缩、两次低于门和同步耗时被保留为风险。

HSDP 减专家：复制轴首次真正执行，配置错误和新型显存墙相继暴露HSDP 4K 端到端通过；长上下文受限

本章回答：数据并行复制数从 1 变为 2 后，哪些过去从未运行的路径会暴露。 S18 S19

Replicate 与材质化假根因

现象与根因：HSDP 专家栈先遇 placement.dim 属性错误；随后三轮 OOM 看似与 EP/重算/优化器换出无关，一度怀疑 to_empty 整栈材质化。

处理与结果：补 Replicate placement 守卫，并用 CPU 机制探针证伪整栈材质化假说。逐参数取证最终发现 config 仍声明 384 专家而权重只有 64 个；物化 config 并改为 64 后，装载/前向/反向通过。

HSDP 专属归约缓冲

现象与根因：复制=2 首次执行 Engram 跨副本稀疏梯度归约，NPU 中转与 HCCL 直连驱动申请约 401MiB；expandable_segments 不能回收这部分。

处理与结果：扩为八节点 数据并行复制 2 × 分片 16 × 上下文并行 2 × 专家并行 32，并在 4K 档释放激活空间。三步 GRPO 七判据全过，Pearson=0.999803/0.999551/0.999671，HBM 峰值 41.04GiB。

16K/32K 不是同一堵墙

现象与根因：32K/16K 主要死在 MoE 专家中间激活；8K 已过反向却死在优化器步 Engram 归约。

处理与结果：不能统称“显存不足”后盲目加 EP。4K 是当前八节点减专家已验证档；归约 CPU 化补丁作为后续长上下文方案，未写成已验证事实。

长训一致性衰减：逐类权重审计取代“重载成功”的表面判据两类静默漏传已修复并值级核验

Attention Sink 静默丢弃

现象与根因：serve 的 weight_loader 没有承接 attn_sink，且已被标为消费，普通缺键清单不可见；长训 Pearson 斜率约 -3.16e-4/步。

现象与根因：训练侧 aux-loss-free 负载均衡 hook 每步更新 e_score_correction_bias，旧导出规则却将对应 gate.bias 当运行态键丢弃。

处理与结果：40 层偏置以 fp32 纳入导出，解除鉴别性冻结。补键后早期衰减斜率显著塌缩，推理值与检查点逐位相符。

Engram 与派生键口径

现象与根因：Engram 表不走主权重，运行态 fp32 副本也不在训练核；coverage_ok=False 来自旧扩展协议字段缺失。

处理与结果：建立七类权重审计：主权重、专家、Attention Sink、路由偏置、Engram、派生键和延迟加载键分别判读，不再用一个 coverage 布尔值覆盖所有语义。

现象与根因：DAPO 退化时各概率层内部双引擎差值均增长，不能只归因于低概率 token 占比或响应变短。

处理与结果：下一步固定权重、固定 prompt/token、温度 1.0、零更新，对健康/塌缩权重分别重复回放并改变并发；预注册已完成，报告不把后续实现提交当作实验结果。

遗留问题：现在还不能声称什么

本章回答：下一位接手者应该把验证预算花在哪里，而不是重跑已经闭合的链路。

1 · 长训双引擎逐 token 分歧：未闭合

DAPO 退化中各概率层内部的训练/推理差值均上升。尚不能定位到具体算子、权重通道或推理运行期状态；温度 1.4 的旧实验还存在观测口径差，不能用于归因。

已规划的判别：固定权重和固定 token，健康/塌缩两臂，各做并发 1 重放与并发 8 重放，零参数更新。预注册已落盘；最新回放代码提交不等于实验已完成。 S22 S23

2 · HSDP 16K/32K 与 Engram 归约 CPU 化：方案存在，验收未统一闭合

4K 已验证，16K/32K 的 MoE 激活墙和 8K 的约 401MiB 跨副本归约缺口是不同问题。归约中转 CPU 化是已提出的框架补丁方案；报告不把它写成已部署并通过长上下文验收。

3 · 集群与框架上游债

早期 --privileged 是设备访问绕行而非集群根治；FSDP/SPMD 尺寸 1 轴契约、Engram 短写、Attention Sink loader 等需要按各自上游状态跟踪。仓库补丁存在不代表上游已合入。

4 · 训练效果不能只看链路

全量 24 步运行出现响应长度塌缩、两次 Pearson 低于 0.995 和奖励噪声；HSDP 历史运行也经历策略退化。本报告是适配回溯，不把一次 pass@1 提升当作所有配置上的能力保证。

可复用的最终经验：先固定真实权重和运行环境，再逐层验证引擎契约；权重同步必须证明“值已生效”，数值一致性必须绑定同一批 token 和同一温度定义；长训结论必须能经受逐类权重审计和固定输入反证。
