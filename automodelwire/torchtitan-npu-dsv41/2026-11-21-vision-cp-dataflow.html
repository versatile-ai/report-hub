先把答案钉死:四个对象、两种命运

整个流程只需要盯住四个对象。上下文并行(CP=2,两卡合算一条序列)对它们的处置完全不同:

对象在两张卡上一句话原因
文本解码器 40 层的权重切分(每卡 1/16,前向临时拼回)FSDP 参数分片铺满全部 16 张卡(CP=1 时沿数据分片 16 单轴,CP=2 时沿数据分片 8 × CP 2 双轴,每卡占比不变);前向逐层 all-gather 拼全量、用完即弃。⚠️ 本图以一对卡示意"分片+拼回"的机制,非完整 16 卡比例 —— 完整集群图见 20261121-vision-cp-cards-map.html
视觉塔权重(0.8B)切分(每卡 1/16,前向临时拼回)与文本权重同一套 FSDP 机制;塔的计算量小,分片省显存是主要动机
图像内容(patch 流、塔输出特征库)完整复制(每卡一份,永不切)视觉塔没有 token 序列轴可切;两卡各自跑一遍完整塔,输出同一份特征库——冗余但语义零冲突,冗余算力约 0.8B 前向 ×1,可忽略
Token 序列(含图像占位 token)切分(每卡每篇文档的一半)CP 的本职:按"每篇文档第 0/1 块"重排后均分;图像占位对解码器而言就是普通 token,跟文本一起被切,没有豁免

一句话总纲:权重和 Token 都切,但切的方式与原因不同——权重按"参数维"切给两卡分摊存储(内容上每卡只有一半),Token 按"序列维"切给两卡分摊计算(每卡看到的行数减半);唯独图像内容既不切也不省,原样两份。"视觉层 CP 与文本层 CP 解耦"说的就是这个:图像内容路径与切分机制无关,而不是存在两个可以分别开关的并行度。

同一置换后各拿一半 卡 0 拿到的 token 流(每篇文档的前半) 题面前半 图像占位·前半 卡 1 拿到的 token 流(每篇文档的后半) 占位·后半 题面后半 图像内容:两卡各一份,永不切分 图像 patch 张量(整图像素块) + 图像网格表(每图宽高) 视觉塔(完整 0.8B 权重经 FSDP 临时拼全)跑整图 → 特征库 [V × D](全部图像特征) 注:注意力需要的 K/V 隐状态怎么办? 卡 1 的"题面前半"作为历史上下文,卡 0 算自己那半行的注意力时必须能看到它 —— 机制 = 注意力核心边界上声明式 all-gather:每层把两卡的 KV 临时拼成整行,算完即弃(方向:卡0→整行←卡1)。 每卡的注意力元数据里记着"我可以看到序列的全长多少"(reach),因果上限锚在自己分片段的末尾,不会看到未来。 边界情况:如果一张图的占位 token 恰好全落在卡 1 的行里,卡 0 一个占位都没有 —— 注入函数走"乘零"空路径,梯度仍然连通,视觉塔参数照常训练。
文本 token / 文本簿记 图像占位 token / 图像簿记 整行复制(不切) FSDP 参数分片(切)
没有为图像新增任何通信:特征库是复制不是交换,注入是本卡局部操作 4. 切分输入时的"置换+均分"是本卡本地操作(全量本来就复制在各卡),零通信 5. 权重的逐层 all-gather 属于数据并行机制(FSDP),与 CP 无关,任何并行形态都有
