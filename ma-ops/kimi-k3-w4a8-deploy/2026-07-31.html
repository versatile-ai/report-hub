部署流程

Step 1
选出 8 个 NPU 空闲节点（5 Cluster A + 3 Cluster B），确保每个节点 /data_nv0 有 ≥1.4T 空间
Step 2
从 NFS (/data/model/Kimi-K3-w4a8/) 用 cp -r 拷贝 1.4T 模型到各节点本地 NVMe (/data_nv0/models/Kimi-K3-w4a8/)
Step 3
加载 Docker 镜像 quay.io/ascend/vllm-ascend:kimi-k3（已在共享盘 /data/l00619320/images/kimi_k3_quay.tar）
Step 4
先启动 Node 0 (start_node0.sh)，再启动 Workers 1-7 (start_worker.sh)
Step 5
等待 ~55 分钟（10min 权重加载 + 45min cudagraph 编译），验证 /v1/models
结果：首次部署即成功，模型返回正常。关键修复：容器启动命令中补充 source custom_transformer/set_env.bash 和 PYTHONPATH，解决了 cudagraph 编译 OOM。

关键修复

问题：cudagraph 编译时 NPU OOM

镜像 quay.io/ascend/vllm-ascend:kimi-k3 的 Docker Entrypoint 只 source 了 CANN toolkit 环境，但 没有执行官方文档要求的 custom_transformer 环境加载：

# 官方文档要求但镜像 Entrypoint 未执行的：
source /vllm-workspace/vllm-ascend/vllm_ascend/_cann_ops_custom/vendors/custom_transformer/bin/set_env.bash
export PYTHONPATH=/vllm-workspace/vllm-ascend:${PYTHONPATH:-}

缺少这两步导致自定义 NPU 算子加载异常 → 内存管理混乱 → cudagraph 捕获时申请 36GB 临时工作空间失败 → OOM。

解决方案

Docker 启动命令改为通过 bash -c 在执行 vllm serve 之前 source 环境：

docker run ... $IMAGE bash -c "
    source .../set_env.bash &&
    export PYTHONPATH=... &&
    exec vllm serve ..."
效果：cudagraph FULL_DECODE_ONLY 编译成功，NPU 内存使用正常（34GB 权重 + 空余），无 OOM。
